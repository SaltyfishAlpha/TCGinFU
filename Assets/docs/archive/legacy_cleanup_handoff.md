### L-5 为什么保留窗口

窗口与当前架构**完全一致**：它走的是正式界面同一个 `BattleSession`，已经支持命刻之战。
它能把全部状态和战报平铺出来，可以按种子复现，编辑器里直接开，不用进 Play——
这些对查规则问题仍有价值，F1 调试浮层替代不了。
过时的只是它默认的哥布林预设，所以随 L-4 一起清掉即可。

## 2. 测试怎么迁（L-3 的前置）

**原则**：测试守的是**规则**，不是样例卡。规则引擎没变，这些断言大多仍然有效，只是换个测试数据来源。

| 现有测试 | 处理 |
| ----- | ----- |
| 断言引擎规则的（属性克制、暴击叠乘、流血轮末结算、见切时机、条件型升变解锁、充能词条放大、危机词条、持续牌进持续区、武器牌伤害跟随装备…） | **迁到 `TestFactory`**（引擎测试已经在用的构造器），就地造一张最小卡，不依赖任何内容 |
| 断言内容完整性的（「样例卡组通过构筑校验」「覆盖四种来源」「脚本钩子全部已注册」「发牌后 30 张」） | **改成对 JSON 内容包断言**。`LegacyContentTests` 已经有加载内容包的写法，可以照抄 |
| 冒烟测试（「打完一局不卡死」「对首领的长局不卡死」、`BattleSessionTests` 的各预设自动打完） | **改成用命刻之战跑**，多跑几个种子 |
| 只对样例数值有意义的（例如某预设几轮能赢） | 直接删 |

> ⚠ **不要在删内容的同一步里删测试**。先迁移，确认测试数不掉、全绿，再删样例内容。
> 迁移前基线：227 个（194 个 `[Test]` + 33 个 `[TestCase]`）。迁移后数量可以减少，
> 但**删掉的每一个都要能说出它守的规则由哪个新测试接手**。

### 内容包加载失败时怎么办

现在会退回样例卡组，还弹一句「已退回样例卡组」。删掉样例内容后改成：
**直接显示加载报告（哪个文件、哪一行出错），不开局。**
这样反而更好：静默退回到另一套内容，会让「内容包坏了」看起来像「游戏能玩」。
这也顺带处理了核对报告的 B-12（加载警告在游戏里看不到）。

### 5.4 顺带改到的东西

- **`BattleSession`**：去掉 `PartySize`（阵容由内容包决定）；`Engine` 可为 null，新增 `IsLoaded`；
  `State` / `SelectedPlayer` 改成 null 安全；`Log` 在没开局时返回加载报告。
- **`BattleView`**：加载失败时走 `BuildLoadFailureScreen()`——整屏报告 + 「重试 / 退出」，
  不建棋盘也不建相机（此时 `State` 是 null，碰什么都会空引用）。「重试」会重新读内容包，改完 JSON 不必重开游戏。
- **`SandboxGui`**：加载失败时摊开报告 + 「重试」；去掉队伍人数与敌人预设选择器。
- **`BattleDebugOverlay`**：没开起局时不绘制。
- **`BattleScenario`**：按策划决定**保留枚举**，只留 `命刻之战` 一个值，作为以后挂新内容包阵容的位置。

### 5.5 留给策划的一个问题

`T04_内容包覆盖除英雄技能牌外的全部结算形态` 里排除了 `CardKind.Hero`：
**整个内容包一张英雄技能牌都没有**。按 §3.3，英雄技能牌要求所属职业满 10 级精通，
而命刻之战的两名角色都没到，所以这在规则上是自洽的，属于**内容待补**而非代码缺陷。
等内容包补上英雄技能牌，把那条排除删掉即可（测试里已写了提示）。
