## 0. 背景

规则书里充能有三种用途，三选一：回复 5 MP、换 +1 AP、支付卡面上「消耗 X 个充能」的词条。现状有两个问题：

- **B-15**：正式 3D 界面里几乎消耗不了充能。
  - 抵 MP 只有调合·万能灵药会弹窗问。
  - 换 AP 只有沙盒有按钮。
  - 暗夜剔骨的可选消耗没有入口。
- **B-16**：`HandlePlayCard` 里 `ChargeSpent = ChargeForMp + cost.Charge`，抵 MP 的充能也被算成支付词条。所以暗夜剔骨用 1 个充能抵掉 5 MP 的同时，还会触发「必定暴击 + 抽 1」。

## 1. 规则改动（已拍板）

| 用途 | 什么时候做 | 怎么做 |
| ----- | ----- | ----- |
| **转 MP** | 单独一个动作，不和出牌绑定 | 消耗 1 个充能 → 立即回复 5 MP，不超过上限。走正常的回复 MP 路径，所以会触发「回复 MP 时」类效果，也计入回复统计 |
| **换 AP** | 单独一个动作（已有 `SpendChargeForApAction`） | 不变：只限玩家阶段，+1 AP，轮末清零（R-10） |
| **支付词条** | 出牌时，跟着这张牌一起提交 | 只有卡面带「消耗 X 个充能」的牌才问；这里的充能数就是 `ChargeSpent` |

**一个充能只算一种用途**：转 MP 的充能不计入 `ChargeSpent`。

旧裁定「出牌时抵扣、不找零」作废，`PlayCardAction` 不再有抵 MP 这回事。

## 2. 引擎（Core）

1. **新动作 `SpendChargeForMpAction(actorId)`**
   - 合法时机：`PlayerActions` 阶段且该角色还没宣布行动完毕，或者 `EnemyResponse` 窗口里该角色可以响应。响应牌也要花 MP，比如看破闪避要 5 MP。
   - 充能区为空就拒绝。
   - 效果：`SpendCharge(actor, ChargeUse.ConvertToMp)`，然后走和卡牌 `restore_mp` 相同的回复路径回 5 MP，不超过上限。
   - 满蓝时**不拒绝**，照样消耗充能（玩家可能就是想清掉充能区），但界面要提示「MP 已满，会浪费」。
2. **`PlayCardAction`**
   - 去掉 `ChargeForMp`。
   - 换成 `ChargeForEffect`：玩家选择额外支付给卡面词条的充能数。
   - `ChargeSpent = ChargeForEffect + cost.Charge`，全部记为 `ChargeUse.PayCardCost`。
   - 校验：`ChargeForEffect` 不能为负；不能超过这张牌允许的上限（见 §3）；充能不够就拒绝。
3. **事件**：转换时战报要能看出是「充能转 MP」，而不是卡牌回复，方便沙盒和战报核对。

## 3. 内容：哪些牌可以选「额外消耗充能」

现在只有两张：

| 卡 | 可选消耗 | 现在的写法 |
| ----- | ----- | ----- |
| 调合·万能灵药 | 1 或 2（至少 1） | Lua 里的 `can_play` 检查充能 ≥ 1；界面靠 `CardChoiceCatalog` 写死 |
| 暗夜剔骨（形态牌） | 0 或 1 | Lua 读 `charge_spent`；**没有任何入口** |

**建议**：在卡牌 JSON 里加一个声明字段（比如 `"chargeOptions": [1, 2]` / `[0, 1]`），由界面根据它生成「消耗几个充能？」的提问，不要每张牌在 `CardChoiceCatalog` 里写死一份。后面角色专属牌很可能会以充能为轴（design_backlog O-10），带这种词条的牌会变多。字段名和形状由你定，定下来后写进 `data_architecture.md`。

万能灵药 Lua 里的 `can_play` 改成检查 `charge_spent ≥ 1`，不要再检查「充能区有没有充能」。

## 4. 界面（View）：右键统一成菜单

**操作约定**：
- 左键 = 选中；
- 长按 = 看详情；
- 右键 = 菜单；
- 拖拽 = 移动或出牌。

角色卡的右键现在是「直接看详情，只有能分摊时才出菜单」（`BattleView.OnCombatantContextMenu`），要改成**总是弹菜单**，和手牌的右键一致。长按看详情保持不变。

**我方角色卡的右键菜单**（主语是被右键的这名角色，用的是**他自己**的充能区）：

| 菜单项 | 条件 | 不可用时 |
| ----- | ----- | ----- |
| `充能换 1 AP（剩 n 个充能）` | 玩家阶段，没宣布行动完毕，n ≥ 1 | 置灰，写原因：「没有充能」「只能在玩家阶段」「已宣布行动完毕」 |
| `充能回复 5 MP（剩 n 个充能）` | 玩家阶段或他的响应窗口，n ≥ 1 | 置灰，写原因；满蓝时可以点，但文字后面加「（MP 已满）」 |
| `替 X 分摊（各 N 点）` | 照旧，来自 `ShareOptionsFor` | 照旧 |
| `查看详情` | 总是有 | — |

**敌方角色卡的右键菜单**：`设为目标`、`查看详情`。

置灰项沿用现有 `(text, null)` 这种不可点条目的写法。**能不能点一律问引擎**，界面不要自己判断阶段和数量。可以加一个类似 `ShareableTargetsFor` 的查询，比如 `CanSpendChargeFor(actor, use, out reason)`。

**出牌时的充能提问**：
- 只对声明了可选消耗的牌问（§3），选项受充能数限制（沿用 `OptionAvailable`）。
- 答案填 `ChargeForEffect`，`BattleView.cs` 里现在读 `answers["charge"]` 当成 `chargeForMp` 的那一行改掉。

## 9. 执行结果（开发，2026-11-23）

验收项全部做完，EditMode 244 条全绿（L02 也是绿的）。几处和本单写法不同、或本单没预料到的，记在这里：

| 项 | 实际做法 |
| ----- | ----- |
| 卡面声明字段 | 定为 `"chargeOptions": [0, 1]`（整数数组，升序去重）。含 0 表示「可以不消耗」，不含 0 表示至少选一个。暗夜剔骨 `[0, 1]`、万能灵药 `[1, 2]`。引擎按它校验，界面按它生成提问——同一个来源，不会分家 |
| 界面提问 | 「消耗几个充能？」由 `CardChoiceCatalog.For(CardDefinition)` 照 `chargeOptions` **现生成**并排在所有问题最前面，不再每张牌写死一份。万能灵药原先写死的那一问已删掉，它的 `mode` / `element` 两问照旧 |
| 置灰 | `CardContextMenu` 以前拿到 `(text, null)` 只是渲染成一个点了没反应的按钮。现在真的 `interactable = false` 并把文字调暗，否则「不可用」和「可用」长得一模一样 |
| 战报 | `ChargeSpent` 事件的 `Text` 从枚举名改成中文用途（「转 5 MP」「换 1 AP」「支付卡面词条」），三种用途在战报上分得开 |
| 顺手修掉的 bug | `LuaProxies` 里 `ctx.choice(key, default)` 读的是 `args[1] / args[2]`——那是外层 `__index` 的 `(table, key)` 下标，不是这个函数自己的。于是**所有二选一永远静默退回默认值**：万能灵药选了元素涂油照样回血回蓝，元素增殖炸弹选属性、炼金防护力场选排位也一样无效。改成 `args[0] / args[1]`。F09c 这条新用例就是撞出它来的 |

本单范围外、但做的时候发现的：**B-2（玩家挑的牌被忽略）仍然存在**，`ChargeFromZone` 还是取弃牌堆顶，和这次改动不冲突，留在 `known_issues.md` 里。
