## 1. 拆分

### 1.1 地图拆成什么

地图在数据上拆成三层，坐标一律用**归一化坐标**（0–1，左上为原点），换更高分辨率的图不用改数据：

| 层 | 是什么 | 这一版要不要 |
| ----- | ----- | ----- |
| **区域** region | 国家或地带，比如 Ursus、Tyrande。用来归类地点、显示区域名、高亮「可前往的区域」 | 要，但**不要求精确的多边形**：一个区域 = 名字 + 标签位置 + 下属地点。高亮时高亮它下属的地点和标签 |
| **地点** node | 地图上能站上去的点：城镇、探索点、地标。队伍只能停在地点上 | 要 |
| **路线** edge | 两个地点之间能直接走的连线 | 要 |

**移动模型是地点图**：队伍从一个地点沿路线走到相邻地点，不能在地图上任意位置停下。
理由是跑团式探索的移动本来就是一段一段的，「可前往」也就有了明确的定义：相邻、而且路线已经解锁。

区域的精确轮廓（按颜色把每个国家抠成可点击的面）**放到第二版**。届时用一张同尺寸的颜色索引图做命中检测，不改这版的数据。

## 2. 要做的东西（按顺序）

### M1 数据与加载

- 新文件 `Content/maps/world.json`：地图图片、区域、地点、路线、任务、开局队伍。
- 格式和战斗内容包同一套写法：JSON、缺字段有默认值、出错进加载报告、不开局。字段名你来定，定下来写进 `data_architecture.md`。
- 每个地点：`id`、`name`、`region`、`type`（城镇 / 探索点 / 地标 / 任务点）、`pos`、`hidden`（初始不显示）。
- 每条路线：两端、`locked`，再预留 `cost` 字段，第一版不用。
- 每个任务：`id`、`name`、`giver`（在哪接）、`target`（目标地点）、`state`（未接 / 进行中 / 完成）、`description`。
- 角色直接引用现有的 `characters/heroes.json`，不另写一份。

### M2 探索模型（纯 C#，不引用 Unity）

新程序集，比如 `TCGinFU.Exploration`（`noEngineReferences`），和战斗的 `Core` 一样：同步、动作制、非法动作原样拒绝、所有变化发事件。

| 动作 | 规则（第一版） |
| ----- | ----- |
| 移动小队 | 只能去相邻、并且路线没锁的地点；目标地点必须已显示 |
| 拆分小队 | 把一名或几名角色从小队里分出来，留在**同一地点**，成为新小队 |
| 合并小队 | 两支小队在**同一地点**时可以合并 |
| 探索地点 | 把探索点标为「已探索」；可以由数据配置「探索后显示哪些地点、解锁哪些路线」 |
| 接 / 交任务 | 小队站在 `giver` 地点可以接；站在 `target` 地点可以标为完成 |

要能回答这几个查询：
- 每支小队在哪、有谁；
- 选中的小队能去哪些地点；
- 某个地点上有哪些可做的事。

界面一律问模型，不自己判断规则。附带 EditMode 测试，覆盖上面每条动作的合法和非法两种情况。

### M3 地图视图

- 新场景，菜单 `TCGinFU → 生成地图探索场景`，和战斗场景分开。
- 显示整张地图。**拖拽空白处平移**，**滚轮缩放**；缩放有上下限，平移不能拖出地图边界。
- 路标的图标和文字在缩放时**保持屏幕上的大小不变**，不跟着地图一起放大缩小。
- 调试用：F1 浮层里加一个「点击打印归一化坐标」开关，策划靠它调地点坐标。

### M4 路标

| 路标 | 显示 |
| ----- | ----- |
| **当前位置** | 每支小队一个，叠着成员头像。几支小队停在同一地点时并排摆，不要叠在一起 |
| **探索点** | 未探索 / 已探索两种样式 |
| **城镇、地标** | 各一种图标 |
| **可前往** | 选中一支小队后，它能去的地点和路线高亮，所属区域的名字也一起高亮；锁住的路线画成虚线 |
| **任务** | 可接的任务挂在 `giver` 上，进行中的任务挂在 `target` 上，各用一种标记 |
| **区域名** | 区域标签位置显示区域名 |

隐藏的地点和它的路线都不画。

### M5 队伍与交互

**操作约定和战斗界面一致**：左键选中，长按看详情，右键弹菜单，拖拽移动。

| 操作 | 效果 |
| ----- | ----- |
| 左键点小队 | 选中这支小队，显示「可前往」 |
| 拖小队到地点 | 移动。拖动时合法地点亮绿、非法亮红，和战斗界面一样 |
| 拖小队里的一个头像出来，放到同一地点的空处 | 拆分 |
| 拖小队到同一地点的另一支小队上 | 合并 |
| 左键点路标 | 选中路标，右下角出信息栏：名字、类型、所属区域、状态 |
| 长按路标或小队 | 看详情（地点描述 / 小队成员与 HP、MP） |
| 右键路标 | 菜单：`前往`（需要已选中小队）/ `探索` / `接任务` / `完成任务` / `查看详情`。做不到的条目**置灰并写原因**，原因一律问模型 |
| 屏幕上的小队列表 | 列出所有小队，点一下选中并把镜头移过去 |

预留一个「进入战斗」入口：右键菜单里放一个置灰条目「遭遇战（未开放）」就够，**这一版不要接战斗**。

### M6 角色视角的 HUD

地图之外，每名角色（PC）有一套个人界面。从小队头像或小队列表打开，一次看一名角色；顶部有角色切换。

**角色面板**（只读）：
- 名字、副标题、立绘；
- 职业和等级；
- 四项属性骰；
- HP / MP（当前 / 上限）；
- 装备着的武器牌和防具牌；
- 所在小队和所在地点。

数值全部从现有角色数据和规则推导，**不另存一份**。战斗里怎么算，这里就怎么算。

**卡组配置**：
- **当前卡组**：主卡组 30 张，按类别和打法分组，显示同名张数；带的升变牌会显示它自带的那组形态卡组，形态卡组只读（规则书 §3.1）。
- **卡池**：这名角色可以编入的牌，左右两栏，拖过去加入或移除，右键也能操作。
  - 第一版卡池 = 内容包里该角色学过的职业的职业牌，加上 `owner` 是这名角色的武器 / 防具 / 秘宝牌。
  - 卡牌的获取来源还没设计（design_backlog §2.1），所以**先不做「拥有」这一层**。
- **合法性**：实时调用 `DeckValidator`，有问题就标红，并列出原因。不合法时**允许保存草稿，但提示「这副卡组不能出战」**。
- **卡牌详情**：长按看，复用战斗里的卡牌详情面板。
- **保存**：第一版只存在本次运行里，关掉游戏就没了，不做存档（§4）。卡组数据结构要和 `decks/*.json` 一致，以后接存档时可以直接写盘。

**状态**：两个界面都只读写探索模型里的角色状态。M2 的模型要多带一份「每名角色当前的卡组」，开局时从 `decks/*.json` 读。

## 3. 验收

- [ ] 打开探索场景能看到整张地图，可以平移、缩放，不会拖出边界
- [ ] 两名角色开局在 Commerce；能拆成两队，分别走到不同地点，再走回同一地点合并
- [ ] 选中小队后可前往的地点高亮；锁住的路线是虚线，不能走
- [ ] 探索一个探索点后，它的样式变了；数据里配了解锁的，地点或路线随之出现
- [ ] 能在 Commerce 接「商路护送」，走到 Anti-Ursus-Alliance 完成
- [ ] 右键菜单里做不到的条目置灰，并写明原因
- [ ] 从地图打开任意一名角色的面板，数值和战斗里一致
- [ ] 在卡组配置里增删牌，校验结果实时更新；凑成不合法的卡组会标红并说明原因
- [ ] 探索模型的 EditMode 测试全绿；`bash Tools/check-asmdefs.sh` 通过；战斗部分不受影响

- 接入战斗（遭遇后开打、战后 HP / MP 带回地图）。
